# Quickstart

A POF bundle is a zip of Markdown files, so nothing here needs more than
a shell. The examples come from `ejemplo.pof.zip`, the bundle of a small
fictional company: the whole core and three extensions, hub, data and
loops.

<Steps>

### Open it

```bash
unzip ejemplo.pof.zip -d ejemplo
cd ejemplo
ls
# COMMITS.md  POF.md  channels  connections  extensions  okrs  policies
# roles  routines  skills
```

### Read the manifest

`POF.md` says what the bundle is: the format, the revision of the spec it
follows, the moment it describes, how much it holds and which extensions
it carries.

```yaml filename="POF.md"
---
type: Bundle
format: pof
revision: 2026-10-18
as_of: 2026-10-18T15:35:05.435Z
counts:
  pieces: 8
  subentities: 4
  links: 9
  commits: 12
  changes: 25
extensions:
  - hub
  - data
  - loops
---
```

A reader checks `type`, `format` and `revision` before anything else.
See [The manifest](/format/manifest).

### List the pieces

Every core piece is one file named after its type, in its own folder:

```bash
find . -path ./extensions -prune -o -name '[A-Z]*.md' -print \
  | grep -v -e HISTORY -e COMMITS -e POF.md | sort
# ./channels/whatsapp-ventas/CHANNEL.md
# ./connections/calendario/CONNECTION.md
# ./okrs/crecer-en-empresas/OKR.md
# ./policies/asignacion-de-consultas/POLICY.md
# ./roles/soporte/atencion/ROLE.md
# ./roles/ventas/vendedor/ROLE.md
# ./routines/seguimiento-de-consultas/ROUTINE.md
# ./skills/cotizar/SKILL.md
```

### Follow a link

Links are paths. The OKR says who owns it and which routine moves it:

```yaml filename="okrs/crecer-en-empresas/OKR.md"
---
type: OKR
kind: tactical
title: Crecer en empresas
name: crecer-en-empresas
goal: Crecer en el segmento empresas
links:
  - role: impacted_by
    to: routines/seguimiento-de-consultas
    created_at: 2026-10-18T15:35:05.198Z
  - role: owned_by
    to: roles/ventas/vendedor
    created_at: 2026-10-18T15:35:05.198Z
created_at: 2026-10-18T15:35:05.198Z
updated_at: 2026-10-18T15:35:05.198Z
created_by: user:equipo@acme.example
updated_by: user:equipo@acme.example
---
Más consultas de empresas y más cierres en el trimestre.
```

`routines/seguimiento-de-consultas` is a folder in the same bundle; open
its `ROUTINE.md` and you are there. See
[Documents and links](/format/documents#links).

### Read the history, if it is there

`COMMITS.md` lists every commit; each piece's `HISTORY.md` lists the
changes that touched it, field by field. Both are optional: a bundle
without them is a snapshot. See [History](/format/history).

### Leave the extensions alone

`extensions/` holds what other systems exported: a CRM's contacts and
deals (`hub`), the company's notebooks and wikis (`data`) and its
automations (`loops`). Each one's `EXTENSION.md` says which system wrote
it and in what format. A reader that does not know an extension keeps it as it is.
See [Extensions](/format/extensions).

</Steps>

<Callout type="info">
  Writing a bundle is the same walk in reverse: one folder per piece, its
  attributes as frontmatter fields, its relations as paths, and the
  manifest at the root. [Reading and importing](/format/reading) lists
  what a reader must check.
</Callout>
