# History

A bundle can carry how the organization got here: every commit, and
every change each commit made. The history is optional. A bundle without
it is a snapshot, and is complete as one.

## `COMMITS.md`

At the root: every commit, in order.

```yaml filename="COMMITS.md"
---
type: Commits
commits:
  - id: df9bc256-91c1-4c26-a88a-a9203bd95a3d
    at: 2026-10-18T15:25:01.591Z
    actor: user:equipo@acme.example
    message: Alta del rol de ventas
    via: rest
---
```

| Field | Required | Notes |
|---|---|---|
| `id` | Yes | The commit's id, kept across exports and imports, like a git hash. |
| `at` | Yes | When it happened. |
| `actor` | Yes | Who made it, as the writing system names its actors. |
| `message` | No | Why. |
| `via` | No | How it came in: `rest`, `mcp`, `import` or `system`. |
| `reverts` | No | The id of an earlier commit it undoes. |

## `HISTORY.md`

In each piece's folder: the changes that touched the piece, its
subentities and its links, in the order they happened.

```yaml filename="policies/asignacion-de-consultas/HISTORY.md"
---
type: History
changes:
  - at: 2026-10-18T15:25:01.659Z
    commit: 609545ed-7ff8-4869-b80c-6d0d53b49310
    action: create
    entity: subentity
    target: rules/001-empresas
    diff:
      then:
        from: null
        to:
          label: Vendedor de empresas
          method: fixed
          target: vendedor-empresas
      title:
        from: null
        to: Empresas
      when:
        from: null
        to:
          op: equals
          path: case.segment
          value: empresa
      position:
        from: null
        to: 0
      piece:
        from: null
        to: policies/asignacion-de-consultas
      type:
        from: null
        to: Rule
---
```

```yaml filename="okrs/crecer-en-empresas/HISTORY.md"
---
type: History
changes:
  - at: 2026-10-18T15:25:01.671Z
    commit: bd9b535e-c845-4d89-840a-c71f520eb60a
    action: create
    entity: association
    target: owned_by roles/ventas/vendedor
    related: roles/ventas/vendedor
    diff:
      from:
        from: null
        to: okrs/crecer-en-empresas
      role:
        from: null
        to: owned_by
      to_type:
        from: null
        to: Role
      to:
        from: null
        to: roles/ventas/vendedor
---
```

| Field | Notes |
|---|---|
| `at` | When. |
| `commit` | The id of its commit in `COMMITS.md`. |
| `action` | What happened: `create`, `update`, `archive`, `restore`, `delete`… |
| `entity` | What it touched: `record` (the piece itself), `subentity` or `association` (a link). |
| `target` | For a subentity, its path inside the piece (`rules/001-…`); for a link, its role and the other piece's folder (`owned_by roles/ventas/vendedor`). |
| `related` | For a link, the folder of the other piece. |
| `path` | For what is no longer in the bundle, the last folder of its piece. With `target`, it names a subentity or a link that is gone. |
| `name` | For what never had a path in the bundle (a user who was retired), its name. |
| `type` | For what is no longer in the bundle, its POF type (`OKR`, `Policy`…). Left out when it was not a piece. |
| `diff` | Each field that changed, with its `from` and `to`. See below. |

### The diff speaks the files

A diff names fields the way the documents write them:

| Change of | Fields in the diff |
|---|---|
| a piece | `type` (`Policy`, `OKR`…), `kind` (only in OKR, Channel and Connection, as in their documents), `name`, `title`, `tags`, `archived_at`, each attribute by its own name (`goal`, `require_catch_all`) and its annotations by their path (`annotations/1`). |
| a subentity | `piece` (the folder of its piece), `type` (`Rule`, `KeyResult`, `File`), `position`, `archived_at` and each attribute by its own name (`title`, `when`, `then`). |
| a link | `from` and `to` (folders), `to_type` (the POF type of `to`), `role`, `archived_at`. |

An attribute whose name is one of those fields keeps an `attributes.`
prefix in the diff.

A `kind` is always one the family has today. A type the writer's catalog
retired is written as the type the piece moved to, or, if it never
moved, as the one it has now. If there is none, the diff leaves `kind`
out.

### Nothing is named by id

Everything in a history is named by path. What is still in the bundle
is named by its folder (and `target`). What is no longer there is named
by the last path it had:

- a deleted piece, by `path`, its last folder;
- a subentity or a link that is gone, by `path` and `target`;
- what never had a path, such as a retired user, by `name`.

Relations toward something deleted use that same last path. A
`HISTORY.md` at the root keeps the changes whose piece is no longer in
the bundle, each with its POF `type` and its last `path`. Here, a role
that was deleted:

```yaml filename="HISTORY.md"
---
type: History
changes:
  - at: 2026-10-18T15:25:01.925Z
    commit: 302e9d16-a0b0-4fb1-b473-9132a11d8719
    action: delete
    entity: record
    type: Role
    path: roles/ventas/cotizador
    diff:
      instructions:
        from: Armás las cotizaciones que te pasa el vendedor.
        to: null
      team:
        from: ventas
        to: null
      type:
        from: Role
        to: null
      name:
        from: cotizador
        to: null
      tags:
        from: []
        to: null
      title:
        from: Cotizador
        to: null
---
```

An annotation is named by its path inside the piece. Adding one is an
update of the piece:

```yaml filename="policies/asignacion-de-consultas/HISTORY.md"
---
type: History
changes:
  - at: 2026-10-18T15:25:01.689Z
    commit: e0a7b5cb-d9a8-47a4-b08b-15e87aa497ed
    action: update
    entity: record
    diff:
      annotations/1:
        from: null
        to: Revisar los turnos si entra un vendedor nuevo.
---
```

An importer gives a new id to each thing it finds named.

The only id in a bundle is a commit's own: commits are identified by
their `id`, like a git hash, and `commit:` and `reverts` reference it.
Everything else goes by path.

<Callout type="info">
  The history and the snapshot must agree: replaying every change in
  order gives the pieces as they are written. A `HISTORY.md` without a
  `COMMITS.md` is an error, since its changes would name commits that are
  not there.
</Callout>

## A bundle without history

An importer takes a bundle without `COMMITS.md` as a creation: one commit
by whoever imports it, with a `create` for every piece, subentity and
link. The pieces end up the same; only their past starts at the import.
