# Extensions

The core holds what every organization has. Everything else a system
keeps (a CRM's pipelines and deals, a data platform's notebooks and
wikis, an ERP's invoices, a BI tool's dashboards) travels as an
extension: a folder under `extensions/`, named after the system's
namespace.

Anyone can write an extension, for any system, without asking the spec:
`extensions/tango/` for an ERP, `extensions/powerbi/` for dashboards.

## `EXTENSION.md`

Every extension starts with its manifest:

```yaml filename="extensions/data/EXTENSION.md"
---
type: Extension
name: data
system: nicetry data
format: data-export/1
spec: https://data-mesk.onrender.com/llms.txt
---
The notebooks and wikis of the business, as the nicetry data engine exports them (its own format, `data.md` is its manifest).
```

| Field | Required | Notes |
|---|---|---|
| `type` | Yes | Always `Extension`. |
| `name` | Yes | The namespace, the same as the folder. It is listed in the bundle's [manifest](/format/manifest) under `extensions`. |
| `system` | Yes | The system that produced it. |
| `format` | Yes | The format of its contents, as that system names it (`data-export/1`). |
| `spec` | No | A link to the documentation of that format. |

## Inside an extension

An extension follows the same rules as the core: Markdown with YAML
frontmatter, `type` always present, empty fields left out, identity by
folder, relations as paths, access state left out. Beyond that, its
layout is its system's.

Its types carry its namespace, so a document says which system it
belongs to wherever it ends up: the data extension writes
`type: data.notebook`, `type: data.wiki` and `type: data.page`. A type
without a dot is a core type; a type with one belongs to the extension
named before the dot. An extension can describe its own types (their fields, what each
one means) in documents of its own, so that a reader understands them
without knowing the system. An extension can carry binary files too.

## References

Inside an extension, paths are relative to its folder. To point outside
it, at the core or at another extension, an extension writes a path from
the root of the bundle with a leading `/`: `/roles/ventas/vendedor`,
`/extensions/data/wikis/manual-de-ventas`. The core points into an extension
through its folder, `extensions/<system>/…`. A reader resolves a path
that starts with `/` against the root of the bundle. See
[Paths across the bundle](/format/documents#paths-across-the-bundle).

## History

An extension can keep its own history (its `COMMITS.md` and
`HISTORY.md`), with the same shape and the same rules as the
[core's](/format/history): types by `type`, with the extension's
namespace (`data.notebook`), and everything named by path, never by id.

<Callout type="info">
  **Readers keep what they do not know.** A reader that does not know an
  extension keeps it intact: it neither drops it nor rewrites it. An
  importer takes the core and the extensions it knows how to read, and
  leaves the rest as it found it.
</Callout>
